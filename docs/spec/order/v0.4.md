> `browser_network_request` で取れなくなるため。現在の手順は `.claude/skills/order/SKILL.md` を参照。

v0.3 の vision-first は「画面（canvas）が唯一信頼できる情報源」という前提だった。
実際には、Flutter は表示用のデータを Stailer の gRPC-web API から取得しているので、
**その応答を読めば画面を見ずに正確な商品データが得られる**。v0.4 ではこれを操作の部品にする。

## 分かったこと

- API は `https://rpc.stailer.jp/stailer.<Service>/<Method>`、形式は `application/grpc-web+proto`（protobuf バイナリ）
- 認証は Firebase の ID トークン（Bearer）。**こちらでは一切扱わない**。リクエストはすべてブラウザ自身に送らせ、応答を読むだけ
- アプリのブラウザペインでは別ドメインの通信が見えず、XHR へのフックも wasm 版 Flutter には効かなかった。
  **Playwright MCP の通信記録（CDP）なら応答の中身まで取れる**

| 用途 | メソッド | 備考 |
|---|---|---|
| キーワード検索 | `ShopService/SearchEcProductsWithKeyword` | req: `1`=キーワード, `6`=ページ, `7`=件数。スクロールで次ページが追加で呼ばれる |
| 商品詳細 | `ShopService/ListEcProducts` | `/product_detail/<商品ID>` を開くと呼ばれる。商品メッセージは検索と同じ形 |
| カート追加 | `ShopService/AddToCart` | req: `1`=商品ID, `2`=新規追加なら1, `5`=経路（`search` / `increment_amount`）, `6`=キーワード。**呼ぶたびに 1 個増える**。応答は本文なしで trailer の `grpc-status: 0` が成功 |

- カートの「−」（数量減・削除）は `rpc.stailer.jp` を通らない（別経路。未調査・今回の範囲外）
- 受け取り日時が未設定でもカート追加はできる

### 商品メッセージの主なフィールド

| field | 意味 |
|---|---|
| 2 | 商品 ID（`/product_detail/<ID>` の ID） |
| 3 | 商品名 |
| 7 / 9 | 価格（税抜 / 税込）。グラム売りは最大重量時の価格 |
| 10 | **在庫なしフラグ**（1 = 在庫なし）。画面の「在庫なし」と一致することを確認済み |
| 16 | 注意書き |
| 52 | バッジ（`2` = ラベル。例: おすすめ） |
| 68 | 100g あたり価格（税抜） |
| 69 | 容量表示（例: `190g`）。グラム売り以外は空のことがある |
| 70 | グラム売り: `1`=価格(目安/最小/最大・税抜), `2`=重量(目安/最大/最小), `3`〜`5`=目安/最大/最小の(税込, 税抜)文字列 |

## 部品

### 検索 → 候補一覧 JSON

1. `browser_navigate` で `https://www.life-netsuper.jp/product_search_results?keyword=<URLエンコードした語>`
2. `browser_run_code_unsafe`（filename: `scripts/playwright/wait_search.js`）で検索 API の応答を待つ
3. `browser_network_requests`（filter: `SearchEcProductsWithKeyword`）で番号を確認し、
   `browser_network_request`（part: `response-body`, filename: `.playwright-mcp/<名前>.body`）で保存。
   ページ追加分も同様に保存する
4. `ruby scripts/life_netsuper.rb products <file>...` → `{ "products": [...] }`（商品 ID で重複除去して結合）

### 商品情報

1. `browser_navigate` で `/product_detail/<商品ID>`
2. `ListEcProducts` の応答を保存し、`ruby scripts/life_netsuper.rb products <file>`

### カート追加

1. ビューポートを縦長（例: 1024x1400）にしておく
2. `browser_navigate` で `/product_detail/<商品ID>`
3. `browser_run_code_unsafe`（filename: `scripts/playwright/add_to_cart.js`）
   - semantics を有効化し、「カートへ追加」ボタン（DOM 順で先頭 = メイン商品）の座標を実マウスでクリック
   - 実際に飛んだ `AddToCart` の**リクエストに商品 ID が入っているか**と `grpc-status` で成否を判定し、
     `{ ok, product_id, sent_product_id_matches, http_status, grpc_status }` を返す
   - 数量 N 個は、成功を確認しながら N 回繰り返す

### 注意

- semantics のボタンに Playwright の `click()` を使うと、DOM だけスクロールして canvas とずれ、別の場所（商品画像など）を押す。
  必ず座標を取って `page.mouse.click` し、ボタンが画面外なら失敗として返す
- 関連商品の「＋」も同じ「カートへ追加」という名前。誤爆は `sent_product_id_matches` で検知する
- `browser_network_request` で保存した**リクエスト** body は、テキストとして保存されるため 0x80 以上のバイトが化けることがある。
  応答 body は問題ない。リクエストの中身を検証したいときは `add_to_cart.js` のようにブラウザ内で確認する
- `browser_run_code_unsafe` の実行環境には `URL` などのグローバルがない
