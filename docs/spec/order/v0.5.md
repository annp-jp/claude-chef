# order v0.5 — 商品選びの判定: Jev と Claude の比較

Issue: annp-jp/claude-chef#5

v0.4 で検索結果を JSON で取れるようになったので、「買い物リストの項目にどの商品を入れるか」を
誰に判定させるかを比べた。

## 結論

- **判定のメインは Claude**（`/chef order` のセッション内でその場で判定する）
- **Jev（TypeSafe）はアダプターとして残す**（`scripts/jev.rb`）。確率のしきい値で「自動投入 / 最後に確認」を
  厳密に分けたくなったら差し替えられるようにしておく
- 精度を左右するのはモデルより**問いの中身**。我が家の基準（いつもの商品優先・安さ・容量など）と
  判断材料（注文履歴など）を問いに入れることが次の課題

## 比較（2026-09-26）

同じ問い（`scripts/jev.rb choose --dry-run` が作るリクエスト）を各 3 回。Claude は `claude -p` に
`--model / --effort / --tools '' / --strict-mcp-config` を付けて実行した（時間には CLI 起動の約 1 秒を含む）。

- 豚こま: 必要量 300g・豚の生姜焼き、候補 7 件 + none
- 牛乳: 指定なし、候補 42 件 + none（豆腐・卵・チーズ・カフェオレなど牛乳以外が 10 件混ざる）

| | 豚こま | 牛乳 | 料金/回 | 選んだ商品（豚こま / 牛乳） | 選択肢の確率 |
|---|---|---|---|---|---|
| Jev | 約 1.9 秒 | 約 2.0 秒 | $0.00006〜0.0002 | あまに豚 290g / あじわい牛乳 1000ml（最安） | 0.62〜0.76 |
| Opus low | 7.1 秒 | 10.4 秒 | $0.028〜0.061 | 国内産 290g / 北海道牛乳 1000ml（広告の品） | 0.40〜0.55 |
| Opus medium | 7.5 秒 | 9.7 秒 | $0.029〜0.059 | 同上 | 0.34〜0.55 |
| Sonnet medium | 5.9 秒 | 9.5 秒 | $0.013〜0.025 | 国内産 290g / 明治おいしい牛乳 900ml | 0.35〜0.55 |
| Sonnet high | 7.0 秒 | 9.7 秒 | $0.013〜0.025 | 同上 | 0.35〜0.60 |

- **正確さ**: 全員、3 回とも同じ商品を選んだ。豚こまは全員 300g に最も近い 290g。牛乳以外の候補はほぼ確率 0
- 違いは**ブランドの好みだけ**（最安 / 広告の品 / 定番ブランド）。問いに我が家の基準がないため、各自の常識で埋めた結果で、優劣はつけられない
- **確率**: Jev は校正されていて合計 1。Claude の確率は 0.35 / 0.55 のような切りのいい値で、合計が 1.05 になることもあり、しきい値には使いにくい
- **説明**: Claude は理由を返せる（「広告の品でお得」など）。最後にまとめて確認するときの材料になる。Jev は確率のみ
- **依存**: Jev は外部サービスと API キーが増える（2026-09 に公開されたばかり）。Claude は既存の仕組みのまま
- `claude -p` は既定だと MCP のツール定義などで 1 回約 28,000 トークン（$0.116）かかった。`--strict-mcp-config` で約 2,800 トークンに減る

### 速度の見積もり

1 品ずつ順に聞くと 25 品で Jev 約 50 秒、Claude 約 250 秒。どちらも**まとめて聞ける**
（Jev は 1 リクエストに複数の質問を入れて並列評価、Claude は 25 品分を 1 回で判定）ので、実際はもっと短い。
並行作業なら速度は決め手にならない。

## Jev アダプター（`scripts/jev.rb`）

```
ruby scripts/jev.rb choose --item 豚こま --amount 300g --dish 豚の生姜焼き --products products.json [--threshold 0.8] [--dry-run]
```

- `--products` は `scripts/life_netsuper.rb products` の出力。在庫ありの候補 + `none` を `choice` の選択肢にする
- 選ばれた確率がしきい値以上なら `auto`、未満なら `ask`、`none` なら `not_found`。`usage`（トークン数）も返す
- API キーは環境変数 `TYPESAFE_API_KEY`、なければ `config/chef.local.yml` の `typesafe.op_ref`（1Password 参照）を `op read` する。キーは表示も保存もしない
- `--dry-run` はキーなしで、送る予定のリクエストだけを出す
