# order

レストランの Chef が仕入れ業者に「発注」する世界観のドメイン。
applied 済み献立の材料を、ネットスーパー「ライフ」のカートに自動投入する。**決済はしない。**

| コマンド | 動作 |
|---|---|
| `/chef order` | ライフのカートに発注（カート投入＋配送枠確保）← 中心 |
| `/chef order list` | 仕入れリスト（発注書）を表示 |
| `/chef order settlement` | 決済（**未実装**。「決済はまだ手動でね」と返す） |

応答は「我が家のシェフ」キャラで。コマンドは `order` だが、口では「発注しとくね」「仕入れリストはこれ」と喋る。

---

## `/chef order list`

直近の確定献立から仕入れリストを生成して表示する（旧 `/chef buy`）。

### 手順

1. `ruby scripts/shopping.rb build` を実行
   - 引数なしで「直近の applied 献立」を自動選択。特定週は `--week-start YYYY-MM-DD`
2. 返ってきた JSON（`categories` がカテゴリ別集計、`pantry_categories` が在庫確認に回すカテゴリ）をユーザー向けに整形して表示

### 出力フォーマット

```
今週（6/1〜6/5）の仕入れリスト:

【肉魚】
- 鮭の切り身  4切れ
- 鶏もも肉    400g

【野菜】
- ほうれん草  1束

【調味料】※在庫確認
- 味噌

【その他】
- 豆腐 1丁
```

注意:
- 同じ食材が複数レシピで使われる場合、`shopping.rb` 側で `+` 合算済（例: `200g + 200g`）。完全な数値合算はしない
- 「確定済み献立がない」エラーが返ってきたら `/chef plan apply` を案内
- `pantry_categories`（既定では `調味料`）は「※在庫確認」をつけて表示する

## `/chef order`

ライフネットスーパーを開き、仕入れリストの商品をカートに自動投入する。**Playwright MCP で AI がブラウザを直接操作する。**

### 役割分担

- **Ruby スクリプト**: 発注対象リストの JSON を出すだけ（`shopping.rb`）。ブラウザは触らない
- **Playwright MCP（あなた）**: ログイン・配送枠確保・検索・カート投入判定・完了報告のすべて

### ⚠️ サイト操作の大前提（ライフは Flutter Web 製）

実機検証で確定（詳細 `docs/spec/order/v0.3.md`）。**通常の DOM もアクセシビリティ(semantics)ツリーも信用しない。**
semantics は canvas(実画面)と desync し、**在庫ありの生鮮が semantics に出ず「在庫なし」と誤判定する**。

**→ vision-first で操作する:**

- **読む**: `browser_take_screenshot` で画面を撮り、**目視**で商品・価格・在庫・「＋」ボタン位置を判断する。
  これが唯一信頼できる情報源（`browser_snapshot` のテキストツリーは在庫ありを取りこぼすので結論に使わない）。
- **クリック**: `browser_run_code_unsafe` の `page.mouse.click(x, y)` で**実座標クリック**。
  同じ座標を二重に押さないこと（数量が増える）。
- **検索ボックスだけは安定 DOM** `input[aria-label="商品を検索"]` に `fill` + `Enter` でよい。
- フルページ遷移後に semantics が要るとき（ログイン画面等）は `browser_evaluate` で
  `document.querySelector('#enable_accessibility')?.click()` → 約2秒待つ。

### 手順

#### 0. 発注リスト取得

1. `ruby scripts/shopping.rb build` を実行し JSON を取得
2. `categories` のうち `pantry_categories`（既定 `調味料`）を**除いた**カテゴリの商品が**カート投入対象**
3. `pantry_categories` の商品は投入せず、最後の「在庫確認リスト」に回す
4. 各商品には `dishes`（使用料理名）が付く。商品選択時の**判断ヒント**に使う
   （例: 肉団子の `dishes=["肉団子スープ"]` ならスープ用 → 味付き不可・素のもの／冷凍で余り日持ち、を提案）
5. 投入対象が空、または「確定済み献立がない」なら、その旨を伝えて終了（`/chef plan apply` を案内）

#### 0.5 ついで買いの確認（献立外の追加品）

献立の材料に加えて、週末のまとめ買い（朝ごはん等）を一緒にカートへ入れたいことが多い。

1. リスト取得後に**必ず聞く**: 「ついでに買うものある？（朝ごはんとか）」
2. ユーザーは自由入力で答える。例:
   `バナナ、牛乳4本、超熟山形6枚切り、ウインナー、ちくわ、ヨーグルト`
3. これを**カート投入対象にマージ**する。各品を「ついで買い」枠の項目として扱う:
   - `dishes` は無し（献立外なので判断ヒントは商品名のみ）
   - **数量指定があれば尊重する**（例「牛乳4本」→ 4個）。指定なしは1個
   - 商品名に規格が含まれれば検索・選択に活かす（例「超熟山形6枚切り」「牛乳」→ Pasco 超熟 山型 6枚 を狙う）
4. 「ない／なし」と言われたらスキップして次へ
5. ついで買い品も投入手順（#4）は同じ（vision-first・在庫ありを目視確認）。
   数量 N 指定のものは「＋」を N 回クリック（毎回スクショで数量バッジを確認しながら）

#### 1. 認証情報の取得

- `ruby scripts/config.rb life-op-item` で 1Password 参照（`op://...`）を取得
- `op read "<op_item>/username"` と `op read "<op_item>/password"` で実値を取得
- 未設定エラーなら「`config/chef.local.yml` に `life_netsuper.op_item` を設定してね（`.example` 参照）」と案内して終了

> 注意: パスワードは 1Password から都度取得し、ブラウザ入力に使うだけ。ファイルやログに残さない。

#### 2. ログイン

1. `browser_navigate` で https://www.life-netsuper.jp を開く。`browser_take_screenshot` でログイン状態を確認
   （右上が「ログイン」ボタンなら未ログイン）
2. **ログイン済み** → 配送枠へ
3. **未ログイン** → https://www.life-netsuper.jp/introduction/login を開く
   - 画面が空なら `#enable_accessibility` を click して semantics を有効化（フォーム入力のため）
   - username / password を入力 → ログインボタンを押す
   - **1回目クリックが無反応のことがある**。URL が `/`（トップ）へ変わらなければ**リトライ**する
   - ログイン失敗時は、その旨を伝えて中断（認証情報の確認を促す）

#### 3. 配送枠の確保（ライフ仕様上、注文前に必須）

1. トップ左の「受け取り日時『設定する』」、または https://www.life-netsuper.jp/delivery_select を開く
2. 予約可能な配送枠（`受付中` の日付・時間帯）を読み取る（当日枠は受付終了が多い）
3. 予約可能な枠を**対話で提示** → ユーザーに選んでもらう
4. 枠を選択 →「受け取り日時を設定」で確保（設定後1時間ホールドされる）
   - 既に枠が確保済みなら、現在の枠を伝えて「このままでいい？」と確認

#### 4. カート投入（vision-first・対話前提）

カート投入対象の商品を**1つずつ**処理する。**原則ユーザーに確認する**
（誤選択を後で入れ替える手間 ＞ 確認の手間。安易な自動選択はしない）:

1. `input[aria-label="商品を検索"]` に食材名を `fill` + `Enter` で検索
2. `browser_take_screenshot` で結果を**目視**。結果が描画されるまで必要なら少し待つ
3. その食材の `dishes`（使用料理）を踏まえ、**在庫ありの**候補を絞って**対話で提示**し選んでもらう:
   - グラム/パックサイズ/形態（味付きか素か・生か冷凍か）の希望を確認する
   - 例: 「肉団子（→肉団子スープ用）、味なしの素のやつでいい？冷凍だと余りが日持ちするけど」
   - ペットフード混入（`犬用/猫用/ちゅ〜る` 等）や別商品（検索の関連表示）は除外する
   - **「在庫なし」と即断しない**。スクショで在庫ありを必ず確認（semantics は当てにしない）
4. 選ばれた商品の緑「＋」ボタン座標へ `page.mouse.click(x, y)`。**二重クリック注意**（数量増）
5. 再スクショでカート点数・数量バッジの増加を確認
6. 数量は **献立の材料は 1 個固定**（DB に数量データなし）。**ついで買い品は指定数を尊重**
   （「牛乳4本」→ ＋を4回）。どうしても在庫あり候補が見つからなければ
   スキップし、最後にまとめて報告（その場では止めない）

#### 5. 完了報告（出力のみ。DB には保存しない）

すべての投入作業が終わったら、結果をまとめて報告する:

```
発注作業おわったよ！

✅ カートに追加できたもの（献立分）:
- 鶏もも肉（若鶏もも肉 300g）
- 鮭の切り身（生鮭 2切れ）
- ほうれん草（ほうれん草 1束）

🧺 ついで買い:
- バナナ（バナナ 1袋）
- 牛乳 ×4（明治おいしい牛乳 1000ml）

⚠️ 見つからなかったもの（手で探してみて）:
- ◯◯

🧂 在庫確認してね（調味料は自動で入れてないよ）:
- 味噌
- 醤油

配送枠: 6/2(月) 18:00〜20:00 で確保したよ。
決済はまだ手動でお願い！
```

- 追加できたもの → 実際にカートに入った商品名（候補から選んだ実物名）
- ついで買い → ユーザー指定の献立外品（数量付き）を別枠で表示
- 見つからなかったもの → 元の項目名
- 在庫確認 → `pantry_categories` の項目

### 注意

- 決済・購入確定はしない（`order settlement` は未実装）
- カートの数量調整はしない（全部 1 個）
- **在庫判定はスクショ（vision）で**。semantics ツリーは canvas と desync するので結論に使わない
- ブラウザ操作中にサイト構造で詰まったら、無理に進めず状況をユーザーに伝えて判断を仰ぐ
- 画面を見ずに通信から検索結果・在庫・カート追加の成否を得る部品がある（`scripts/life_netsuper.rb` / `scripts/playwright/*.js`、手順は `docs/spec/order/v0.4.md`）。
  スクショで迷うとき（在庫の有無、どの商品が入ったか）はこちらで確かめてよい
